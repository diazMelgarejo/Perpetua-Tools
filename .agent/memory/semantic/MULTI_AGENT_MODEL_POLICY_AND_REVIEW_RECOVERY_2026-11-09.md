## Reusable Recovery Procedure

1. Re-read current operator decisions, Gossip claims and live PR heads.
   A previous worker's completion note is a handoff, not independent approval.
2. Record source refs, exact bases and ownership before editing. Keep
   unrelated worktrees and every actor's attributed commits intact.
3. Inventory the entire conflict surface first. Follow per-file operator
   direction where repository rules require it. Preserve both regression
   sets; reconcile behavior rather than selecting a branch wholesale.
4. Verify provider namespace, installed capabilities, policy permission and
   trusted approval as separate contracts. Do not infer one from another.
5. Test refusal paths before durable claims and effects. A callback's Boolean
   success cannot attest evidence its interface does not carry.
6. Validate semantic cross-repository equality before changing pinned
   digests. Preserve historical records and test fixtures intentionally
   rejecting obsolete identifiers.
7. Report exact scan scope, skipped jobs, host gates and known debt. New
   security fingerprints require a bounded rationale, not a blanket refresh.
8. Use the native memory writer for append-only episodes and candidates.
   Keep candidates staged until separately accepted; never hand-edit the
   generated lesson view or silently rewrite historical evidence.
9. Consolidate once, test the final stack, recheck live heads and publish one
   batch per authorized existing PR. Reply inline with the actual fixing SHA.
   Do not report an unpushed local fix as visible on GitHub.
