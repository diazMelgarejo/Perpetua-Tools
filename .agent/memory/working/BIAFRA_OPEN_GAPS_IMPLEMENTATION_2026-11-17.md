## Implementation choices

PT remains spending authority. Its generic OpenAI route refuses W&B before
SDK construction; the dedicated guarded provider alone dispatches that route.
The SDK request runs in a killable child with parent-owned accounting. Known
unsent SDK startup releases; uncertain sent outcomes charge the reservation.
The child carries no ledger and returns a minimal JSON protocol, not provider
objects or credential-bearing errors. Optional tracing stays inside the deadline.

Orama retains one declared metric registry, its existing three-revert policy,
exact integer guards and a live preflight before reservation or marker. The
preflight consumes a pin and same-day local evidence without treating those
records as authentication or inventing provider/account observations.

## Lessons supported by this implementation

- Mocks do not cross an interpreter boundary. After introducing a process,
  move SDK doubles to the runner seam and test the worker with local programs.
- A phase timeout is not a total request deadline. Stop request execution at
  expiration, then distinguish bounded cleanup from active request time.
- Preserve known-unsent outcomes across the worker protocol; do not relabel
  client construction as uncertain dispatch and charge it as such.
- Fresh probe evidence cannot authorize a new model or bypass an effort ladder.
  Derive selection from the canonical policy before reservation and marker.
- Strict preflight must reject invalid launcher inputs before consuming the
  one-attempt marker. Refusal is not a completed or spent attempt.

## Test-isolation incident

An initial run used old parent-side SDK mocks after the process boundary was
introduced. Two confirmed dummy-credential requests received HTTP 401; a third
dispatch cannot be ruled out because that test was interrupted. No operator
credential was used. The run stopped, fixtures were corrected, and subsequent
tests used offline doubles or local-only children. This is an execution error,
not a successful provider probe or billing evidence. Preserve the private
incident artifact and do not repeat the requests to investigate it.
