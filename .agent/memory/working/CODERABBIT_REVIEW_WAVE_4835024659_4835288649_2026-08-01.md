## Batch E — PR-body systemic fix, review #4835288649 (commit `88783688`)

**Common thread:** Agents could still clobber PR bodies via env export, `update_pr`,
`gh pr edit`, or chained shell (`&&`, `;`, `||`). Override must be **operator-TTY-only**
with a **single write path**.

| File | Change |
| ---- | ------ |
| **NEW** `scripts/cursor/grant-pr-body-human-override.sh` | Interactive TTY only; writes `~/.cursor/pr-body-human-override-ack` with `operator-grant-v1` + `issued-at` (8h TTL) |
| `pr-body-guard-core.py` | Grant file validation with TTL; **deny all** `update_pr` body writes; allow `append-pr-body.sh` only when grant active; chained-command segment scan; removed agent-forgeable `CURSOR_PR_BODY_HUMAN_OVERRIDE_ACK` as sole gate |
| `append-pr-body.sh` | Requires valid operator grant file before run |
| `pr-body-backup-lib.sh` | Propagate `gh`/mkdir failures (no silent success) |
| Hook shells | Backup failure → `DENY` (fail-closed) |
| Docs / rules / skills | Removed agent-executable `touch`/`export` override recipes |

**Layer 0 agent rule (final):**

| Allowed | Blocked (always for agents) |
| ------- | --------------------------- |
| `ManagePullRequest post_comment` | `update_pr` with `body` |
| `gh pr comment` | `gh pr edit --body*` |
| | `gh api` PR body mutations |
| | `append-pr-body.sh` without operator grant |
